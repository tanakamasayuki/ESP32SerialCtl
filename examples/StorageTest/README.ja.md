# StorageTest

> English: [README.md](README.md)

複数のストレージのmount結果を調べるサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [StorageTest.ino](StorageTest.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<Arduino.h>`, `<FS.h>`, `<LittleFS.h>`, `<SPIFFS.h>`, `<FFat.h>`, `<SPI.h>`, `<SD.h>`, `<Wire.h>`, `<ESP32SerialCtl.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `Wire.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
2. `esp32SerialCtl.service()` — 保留コマンドを定期的に処理します。呼び出し元を止めると次の入力も遅れます。

変更する前に確認する定数: `PIN_SD_CS`。GPIOやチャンネル、容量などは用途に合わせます。

## APIの使い方と注意点

シリアルを開始し、スケッチの速度にモニタを合わせ、改行付きでコマンドを送ります。`service()` を継続して呼びます。解析とハンドラは呼び出し元の文脈で動くため、遅いハンドラは次の入力を遅らせます。

まず `help` と `sys info` で確認し、各例が初期化した機能だけを試します。登録中はCommandEntry／ConfigEntryの表を有効に保ちます。引数の説明文だけで数値や範囲が検証されるとは考えず、ハンドラでも確認します。

設定はNVSに保存され、リセット後も残る場合があります。GPIOの別名と許可方針を配線に合わせます。ファイル操作は実際にマウントした領域へ作用します。

一部の例はマウント失敗時に初期化するため、試験用ストレージを使い、書き込み前にmountの指定を確認します。

複数のFSをmountし、失敗時の初期化を有効にしています。基板のPartition構成が全FSを持つとは限らないので、FAILを個別に確認します。同じ領域を異なる形式として使わないよう、Partition名と配置を合わせます。

## 操作と出力の見方

出力書式の一部は次のとおりです。printfの書式記号は実行時の値に変わります。表示順や数値は実行条件に応じて変わるので、その行へ進む条件と併せて確認します。

```text
SD mount      : %s
SPIFFS mount  : %s
LittleFS mount: %s
```

## 確認と問題の切り分け

複数のストレージのmount結果を調べることを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
